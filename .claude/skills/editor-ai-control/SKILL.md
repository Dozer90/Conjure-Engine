# Drive the editor as an agent

The editor exposes every edit as a command: one JSON object per line in, one JSON object per line out,
the same catalogue in the UI, over the network and in headless mode. The design is
`docs/design/04_editor.md`; the catalogue dump this page summarises is `docs/generated/editor_protocol.json`
(regenerated by `conjure_editor_tests --conjure-update-golden`, case `editor.schema`). The living truth
is `editor.schema`: ask the running editor when in doubt.

## 1. Start the editor

```bash
build/<preset>/bin/conjure_editor --project <dir>                      # UI, AI server on 127.0.0.1
build/<preset>/bin/conjure_editor --project <dir> --headless --ai-port 47820
build/<preset>/bin/conjure_editor --project <dir> --headless --ai-stdio   # protocol on stdin/stdout
build/<preset>/bin/conjure_editor --project <dir> --headless --exec cmds.json --out out.ndjson --keep-going
```

| Flag | Meaning |
|---|---|
| `--project <dir>` | the project directory (`project.json`); `--headless` without it still runs, `REQUIRES_PROJECT` commands answer `PROJECT_NOT_OPEN` |
| `--headless` | null platform, renderer, audio and script host; no window |
| `--ai-port <n>` | TCP port; default 47820 and nine more are tried when busy; `0` disables the server |
| `--ai-stdio` | requests on stdin, responses and events on stdout, logs on stderr (not with `--exec`) |
| `--ai-token <t>` | every client must present the token in `session.hello` |
| `--exec <file>` | run a JSON array or NDJSON of requests, then exit: 0 all ok, 1 a request failed, 2 the project or engine failed to start, 3 bad arguments or a file that is missing or does not parse (checked before the engine starts, so it fails at once) |
| `--out <file>` | write the `--exec` responses and events to a file (default stdout) |
| `--keep-going` | continue `--exec` after a failed request |
| `--timeout-seconds <s>` | asynchronous replies time out after `s` seconds (default 120) |
| `--offscreen` | render without a window so `view.screenshot` has pixels (falls back to the null device when the configuration refuses) |

The bound port is written to `<project>/.conjure/ai_port`; read it instead of guessing. Connect to
`127.0.0.1:<port>`, send newline-terminated JSON, read newline-terminated JSON. A line above 16 MiB
disconnects the client (`MESSAGE_TOO_LARGE`).

## 2. Wire format

```
-> {"id":1,"cmd":"session.hello","args":{"clientName":"my-agent","token":"..."}}
<- {"id":1,"ok":true,"result":{"protocolVersion":1,"engineVersion":"...","schemaHash":"...","clientId":2,"headless":true}}
-> {"id":2,"cmd":"entity.create","args":{"name":"Player","components":{"transform":{"position":[1,0,1]}}}}
<- {"id":2,"ok":true,"result":{"guid":"a9e2c0d4-...","name":"Player","revision":42}}
<- {"id":3,"ok":false,"error":{"code":"ENTITY_NOT_FOUND","message":"...","details":{"didYouMean":[]}}}
<- {"event":"selection.changed","seq":913,"frame":8812,"data":{"guids":["a9e2c0d4-..."],"primary":"a9e2c0d4-..."}}
```

- `id` is an integer, string or null and is echoed verbatim; `args` is an object (`{}` when absent).
- The first request on a TCP or stdio connection is `session.hello`; with `--ai-token` it carries `token`
  or every request answers `UNAUTHORISED`.
- Events arrive between responses. A new client gets every event except `log` and `command.executed`;
  `session.subscribe {"events":[...],"minLogLevel":"warn"}` changes that. `events.dropped` reports log
  events shed under backlog pressure.
- Asynchronous commands (`asset.import`, `script.compile`, `module.build`, `view.screenshot`,
  `play.step`, `editor.wait_frames`, `editor.exec_file`, `project.export`) answer when they finish, some
  frames later; up to eight may be pending per client (`BUSY` beyond that), each times out after
  `--timeout-seconds` (`TIMEOUT`). Keep sending other requests meanwhile or wait for the id. A
  `project.open` restarts the engine and answers every request still pending with `CANCELLED`
  (an `editor.exec_file` whose file opens a project ends there).
- Error codes: `PARSE_ERROR INVALID_REQUEST MESSAGE_TOO_LARGE UNKNOWN_COMMAND INVALID_ARGS
  ENTITY_NOT_FOUND COMPONENT_NOT_FOUND TYPE_NOT_FOUND PATH_NOT_FOUND ASSET_NOT_FOUND PROJECT_NOT_OPEN
  SCENE_NOT_OPEN WRONG_PLAY_STATE NOT_AVAILABLE IO_ERROR COMPILE_FAILED BUSY TIMEOUT CANCELLED
  UNAUTHORISED INTERNAL`. `UNKNOWN_COMMAND` details carry `didYouMean`; `INVALID_ARGS` names the
  offending `args.<path>`; `COMPILE_FAILED` details carry `diagnostics`.
- Three codes that are easy to confuse: `PATH_NOT_FOUND` is a file or folder that does not exist (an
  `asset.import` source, a `scene.open` file, a `project.open` directory, an `editor.exec_file` file, a
  script, the `distributionDirectory` a `project.export` copies the runtime from, the vanished source file of a
  registered asset)
  or a reflection path that does not resolve; `IO_ERROR` is one that exists but cannot be read,
  or a failed write; `ASSET_NOT_FOUND` is an asset reference (uuid or asset path) that names no asset.

## 3. Discover before you guess

| Command | Answer |
|---|---|
| `editor.schema` | every command with `summary`, `flags`, `args` and `result` JSON schemas; `{"command":"entity.create"}` for one |
| `editor.state` | project, scene, play state, revision, selection, transports |
| `reflection.components` | every editable component type with fields, kinds, defaults, aliases |
| `reflection.type {"name":"camera"}` | one component, struct or enumeration |
| `reflection.asset_types` | asset types, importers, extensions, import option schemas |
| `scene.get_hierarchy {"depth":2}` / `scene.query` | the live scene |

Flags in a descriptor: `mutates` (recorded for undo and marks the scene dirty), `no_undo`, `async`,
`requires_project`, `requires_scene`, `editing_only` (refused while playing), `not_in_batch`, `on_disk`
(an undoable change to the project's files: it survives `play.stop`, see Play mode below).

## 4. Conventions

- **Entities** are referenced by guid string, by hierarchy path (`Board/Cell_3`) or by unique name.
  `entity.find` and `scene.query` list guids; pass guids back, paths are convenience.
- **Property paths** are `<component>.<field>[.<sub>|[i]]`: `transform.position.x`, `sprite.size`,
  `script.scripts[0].fields.mine`, `camera.cameraData.projection`. The component is an alias
  (`transform`, `sprite`, `camera`, `script`, `rigid_body`, ...), a unique suffix (`local_transform`) or
  the full name (`conjure.renderer.sprite.size`). A bare type name addresses the whole component.
  Enumerations accept the name or the number; entity references travel as guid strings.
- **Undo** records every `mutates` command as one entry; `editor.batch {"commands":[...],"atomic":true}`
  makes one entry of many, `editor.begin_transaction` / `editor.end_transaction` group a client's
  commands, `history.undo {"count":n}` / `history.redo` / `history.list` drive it. Undo is frozen while
  playing (`WRONG_PLAY_STATE`).
- **Play mode**: `play.start` snapshots the scene; `play.stop` restores it byte for byte. `play.pause`,
  `play.resume`, `play.step {"fixedSteps":n}` for deterministic stepping; `input.inject` feeds keys, buttons
  and taps. What an edit made while playing leaves behind depends on the command:
  - scene edits (`entity.*`, `component.*`, `prefab.instantiate`, `prefab.unpack`, `script.attach`,
    `scene.set_settings`) are discarded by `play.stop` and never recorded for undo (`warning`
    `UNRECORDED_PLAY_EDIT`, once per session);
  - file edits, the commands flagged `on_disk` (`asset.import`, `asset.create_folder`, `asset.delete`,
    `asset.create_material`, `asset.set`, `asset.restore`, `prefab.apply`, `project.set_settings`,
    `script.create`, `script.write`, `script.delete`), stay on disk (`warning` `PLAY_FILE_EDIT`, once per
    session). `play.stop` answers `fileChanges` (their count) and records them as one undo entry, `File
    changes during play`: one `history.undo` after the stop takes them all back;
  - `prefab.create`, `scene.save` and `scene.save_as` answer `WRONG_PLAY_STATE`: stop first.
- **Determinism for files**: pass `guid` / `guids` / `uuid` to `entity.create`, `entity.create_many`,
  `prefab.instantiate` and `prefab.create` so a command file replays identically.
- **Units and encodings**: angles cross the protocol in degrees (`view.set_camera {"fov":60}`, euler
  rotations), `input.inject {"text":...}` is UTF-8 and injects one text event per code point, and a line
  that is not valid UTF-8 answers `PARSE_ERROR` like any other unparseable line (the client stays
  connected; only an oversized line disconnects).
- **Deleting scenes**: `asset.delete` refuses the file behind the open scene (`INVALID_ARGS`) unless you
  pass `"closeOpenScene":true`, which deletes the file and closes the scene (unsaved changes are
  dropped, the undo history is cleared; undoing the delete restores the file but does not reopen it; a
  delete that fails leaves the scene open). The flag is refused inside `editor.batch`, an open
  transaction, an undo or redo step and during play. Deleting the project's startup scene works
  and emits `warning {code:"STARTUP_SCENE_DELETED"}`: name another with `project.set_settings`.
- **Export** is always a Distribution export: `project.export {"directory":...}` plus
  `distributionDirectory` to copy the runtime. There is no `config` argument (and `project.create` has
  no `template`); sending one is `INVALID_ARGS`, like any unknown argument.
- **Side effects you cannot undo**: `asset.import` of a file already inside `assets://` records no undo
  entry (nothing was created, so undo never deletes a user file); a module's `mutates` command is
  recorded as `no_undo`; `module.build` always runs the `cmake` on the PATH with `config` / `target`
  restricted to plain names.
- **Importers**: a file is cooked by the importer that claims its extension: a `.gltf` / `.glb` is a render
  model (`conjure.renderer.gltf`), an `.obj` a collision mesh. Pass `importer` to `asset.import` or
  `asset.reimport` to use another registered one, such as `"conjure.physics.collision_mesh_importer"` for
  collision geometry kept in its own glTF file; the settings then become that importer's defaults.
- **Scripts** live in `<project>/scripts/`; `script.create` writes a template and `Game.csproj`,
  `script.attach` adds the class to an entity (fields in `script.scripts[i].fields`), `script.compile`
  runs `dotnet build` (`NOT_AVAILABLE` without a .NET SDK, `COMPILE_FAILED` with diagnostics).
- Never name entities, assets or scripts after copyrighted games or characters; the sample game is
  the original Grid Sweeper of `docs/design/17_demo_games.md`.

`script.compiled`, `script.reloaded`, `asset.imported`, `module.state`, `command.executed`,
`client.connected`, `client.disconnected`, `events.dropped`, `warning` (`{code, message}`; codes

When the project's startup scene does not load (missing, corrupt), the editor still starts, over an empty
world, and an `--exec` run still exits by its requests alone. The first line of the output is then
`{"event":"warning",...,"data":{"code":"STARTUP_SCENE_FAILED","message":"..."}}`: check for it before relying
on the scene, or repair the scene in the same file (`scene.new` with its path, then `scene.save`). The same
event follows a `project.open` into such a project.

## 6. Walkthrough: build Grid Sweeper headless

The command file `tests/editor/data/commands/build_grid_sweeper.json` builds the 2D minesweeper-style
demo of `docs/design/17_demo_games.md` 2.1 and is what the e2e tests replay. Run it against any project:

```bash
build/<preset>/bin/conjure_editor --project <dir> --headless \
  --exec tests/editor/data/commands/build_grid_sweeper.json --out out.ndjson
```

Its steps, which are the pattern for any scene an agent builds:

1. `session.hello` then `scene.new {"name":"grid_sweeper","path":"scenes/grid_sweeper"}`.
2. Content first: `asset.create_material` for the cell material, `script.create` for
   `CellBehaviour` and `GameState`, `script.write` to replace a template with real source.
3. A template entity: `entity.create` with a fixed `guid` and `components` (`sprite`), `script.attach`
   with the per-cell fields (`mine`, `adjacent`, `revealed`, `flagged`), moved off-screen with
   `entity.set_transform`, then `prefab.create {"entity":...,"path":"prefabs/cell","uuid":...}`.
4. The board: `entity.create` for `Board`, `prefab.instantiate {"count":64,"parent":<board>,"guids":[...]}`,
   then one `component.set_many` placing every cell (`transform.position`) and setting the mines and
   adjacent counts (`script.scripts[0].fields.mine`, `...adjacent`), so the layout is one undo entry.
5. `GameState` entity with its script fields (`width`, `height`, `mines`), an orthographic `Camera`
   (`camera.cameraData.projection` = `ORTHOGRAPHIC`, `camera.postProcess` = `false` so the sprites keep their
   authored colours), `view.set_mode {"mode":"2d"}`, `view.focus`, `selection.set`.
6. Verify with `scene.query {"with":["prefab_instance"],"fields":["script.scripts[0].fields.mine"]}`.
7. Play-test: `play.start`, `input.inject {"button":"LEFT","position":[320,240],"action":"tap"}`,
   `play.pause`, `play.step {"fixedSteps":3}`, `entity.get` to read state, `play.stop` (the scene is
   back exactly as built).
8. Persist: `scene.save`, `project.set_settings {"settings":{"startup_scene":"scenes/grid_sweeper.scene.json"}}`,
   `scene.info`.

Afterwards `script.compile` builds the C# project when a .NET SDK is installed; without one the reply is
`NOT_AVAILABLE` and the scene is still complete.

## 7. Checklist for an agent session

- Read `<project>/.conjure/ai_port`, connect, `session.hello`, then `editor.schema` once and cache it by
  `schemaHash`.
- Prefer guids; fetch them from the responses of the commands that created the entities.
- Group related edits in `editor.batch` (atomic) so a failure leaves nothing half done and the user has
  one undo step.
- Wait for asynchronous ids before depending on their results; never resend a pending request.
- Stop play (`play.stop`) before saving: `scene.save` is refused while playing, and scene edits made while
  playing are not kept. File edits made while playing are kept; check `fileChanges` in the `play.stop` result
  and `history.undo` once if they were not meant to stay.
- `scene.save` before `editor.quit`, or pass `{"saveChanges":true}` to `editor.quit` (it stops a play session
  before it saves; if the save fails the editor does not quit and stays in the editing state).
