## Blockers

### B1. D3D12 swapchain is destroyed/resized with Present still in flight: Debug runtime crashes at exit (0x87D)

`engine/src/rhi/backends/d3d12/swapchain_d3d12.cpp:57` (bug; found by: Platform and graphics backends)

~d3d12_swapchain (line 57-59, `release_back_buffers();` then the ComPtr releases the swapchain) and resize() (line 174-177 `device->waitForIdle(); release_back_buffers(); device->runGarbageCollection();` then ResizeBuffers) rely on nvrhi waitForIdle, which only waits for NVRHI's own submitted command-list instances, not for the Present queued afterwards on the same queue. The buffers get their final release while the queue still references them. With the D3D12 debug layer on (forced in Debug builds: engine_config.cpp:31 `config.rendering.gpuValidation = CONJURE_DEBUG != 0`) the layer raises an unhandled exception and the process dies.

**Smallest fix:** Give d3d12_swapchain (or d3d12_device_backend) a private ID3D12Fence and a flush helper: `graphics_queue()->Signal(fence, ++value)` then SetEventOnCompletion/Wait, and call it before release_back_buffers() in both the destructor and resize() (after nvrhi waitForIdle). Add a [gpu] test that creates the swapchain on a debug-layer device, presents, resizes and destroys.

### B2. Windowed conjure_editor and conjure_runtime cannot start from a fresh build tree: shaders are built into <build>/shaders but looked up in <exe dir>/shaders

`engine/shaders/CMakeLists.txt:12` (build-ci; found by: Modules and build system)

The shader library is written to ${PROJECT_BINARY_DIR}/shaders, while the engine opens <executable directory>/shaders (build/<preset>/bin/shaders). No build step copies or redirects it, and there is no command-line flag for the shader directory. Every windowed start of both executables fails; only tests and benchmarks work because they pass rendering.shaderDirectory explicitly.

**Smallest fix:** Set OUTPUT_DIR to "${CMAKE_RUNTIME_OUTPUT_DIRECTORY}/shaders" (still inside the build dir, so the existing check passes; tests read the CONJURE_SHADER_OUTPUT_DIR property and follow automatically), and correct repository-layout.md. Add a process test that starts conjure_runtime with --rhi null but the default shader directory, or asserts index.json exists beside the executable.

### B3. Resizing the window kills the app on D3D12: back-buffer framebuffers are still cached when ResizeBuffers runs

`engine/src/renderer/renderer.cpp:1395` (bug; found by: Renderer)

renderer::on_swapchain_resized() is the only place the framebuffer cache drops the framebuffers that hold the swapchain back buffers, and the engine calls it only AFTER swapchain->resize() succeeded. The cached nvrhi framebuffers (tonemap/blit target and the ImGui framebuffer at renderer.cpp:1347) hold TextureHandles on the back buffers, so IDXGISwapChain::ResizeBuffers fails with DXGI_ERROR_INVALID_CALL, the retry fails the same way and frame_loop requests quit.

**Smallest fix:** Drop the back-buffer references before the resize: add a renderer hook called before swapchain->resize() (or call the existing one first in frame_loop::apply_resize, and again on failure paths), i.e. framebuffers->clear() + device wait/GC, then resize. Add a [gpu] test: renderer with a WARP swapchain, render one frame, resize, render again.

### B4. KINEMATIC_MOVES_WITH_TRANSFORM bodies carry an interpolated_transform nobody ever writes, so they render at the world origin

`engine/src/physics/physics_world_sync.cpp:276` (bug; found by: Physics)

Every non-static rigid_body gets scene::interpolated_transform (on_component_added bodies.cpp:164-169, create_body bodies.cpp:543-545), but for a movesWithTransform row the pull skips it (sync.cpp:503-505 `|| row->movesWithTransform || row->hasParent) { continue; }`) and push_hierarchy_rows only does `bodies.MoveKinematic(...); row.lastPulled = pose;` (sync.cpp:276-284) without touching interpolated_transform. scene's propagation renders any entity that has the component from it: transform_propagation.cpp:273-274 `if (self) { renders[row].matrix = math::transform::lerp(poses[row].previous, poses[row].current, alpha).to_matrix();`.

**Smallest fix:** In push_hierarchy_rows for movesWithTransform rows write interpolated->previous = interpolated->current (or pose on firstPull) and current = pose (the push system already declares interpolated_transform as a write), or do not add interpolated_transform to movesWithTransform rows at all; add a test asserting interpolated.current == composed pose after a step.

### B5. Exit code 125 explained: every windowed D3D12 Debug run dies at shutdown with unhandled exception 0x87D

`engine/src/engine/subsystems/rhi_subsystem.cpp:128` (bug; found by: Engine and runtime)

The editor's 125 is the low byte of 0x0000087D (2173), the exception the D3D12 debug layer raises for a CORRUPTION message. It is not an engine exit code and the documented 0-4 table (exit_code.h, docs/api/engine/running-the-engine.md 149, runtime/README.md 40) does not cover it. The shutdown is not clean: the swapchain back buffers are final-released while the last Present is still in flight on the graphics queue, and the process is killed before the log is flushed. conjure_runtime does the same.

**Smallest fix:** In the D3D12 backend, signal and wait on a fence of the graphics queue before releasing back buffers (swapchain destructor and resize), or have device::wait_idle() flush the queue itself. Add a REAL_WINDOW test that runs conjure_runtime windowed for a few frames and expects exit 0.

### B6. Resizing or minimise/restoring the window crashes the process (D3D12, Debug)

`engine/src/engine/frame_loop.cpp:398` (bug; found by: Engine and runtime)

A framebuffer resize goes through frame_loop::apply_resize -> swapchain->resize, which releases the back buffers while DXGI's own present command list still references them. Outside a debugger the process dies with 0xC0000005 inside the D3D12 SDK layers; minimise then restore dies with 0x87D.

**Smallest fix:** Flush the graphics queue with its own fence before release_back_buffers() in d3d12_swapchain::resize, and in apply_resize drop the renderer's swapchain framebuffers before calling swapchain->resize(). Add a REAL_WINDOW test that resizes and minimises.

### B7. --ai-stdio: engine logs are written to stdout and corrupt the NDJSON protocol stream

`engine/src/editor/core/protocol/protocol_server.cpp:60` (bug; found by: Editor commands and protocol)

With --ai-stdio the protocol uses std::cout, but nothing redirects the log console sink, which writes everything below WARN to stdout (core/log.h:131). Design 3.12, the --help text and the docs promise 'logging goes to stderr, never stdout'.

**Smallest fix:** When options.aiStdio (and --exec without --out) is set, switch the console log sink to stderr before the engine starts (or remove it); add a [process] test that parses every stdout line of an --ai-stdio session as JSON.

### B8. script.compile always fails in the shipped editor: ConjureManagedDir is passed as the relative path 'managed'

`engine/src/editor/core/commands/commands_script.cpp:296` (bug; found by: Editor commands and protocol)

engine_config::scripting.managedDirectory is empty by default (engine_config.h:137 'empty = <exe>/managed') and cannot be set from the project or command line; managed_directory() then returns the relative path "managed", which MSBuild resolves against <project>/scripts, so the generated csproj's own check fails every build.

**Smallest fix:** Resolve the default exactly like the scripting subsystem (absolute <engine dir>/managed, or runtime->host managed directory) before passing -p:ConjureManagedDir; make the dotnet test require success when CONJURE_EDITOR_TEST_MANAGED_DIR is defined.

### B9. The default script.create template ('Behaviour') does not compile

`engine/src/editor/core/commands/commands_script.cpp:94` (bug; found by: Editor commands and protocol)

BEHAVIOUR_TEMPLATE assigns to a member of the value returned by the Transform property, which C# rejects; every script created with the default template fails script.compile.

**Smallest fix:** Rewrite the body against the real Conjure.Managed API (e.g. copy Transform to a local ref/struct and write it back, or use the API's setter) and drop `* 0.0f`; add a dotnet-gated test that compiles both templates.

### B10. The Viewport never shows the scene through the editor camera; orbit/pan/zoom, picking and gizmos are disconnected from the picture

`engine/src/editor/ui/panels/viewport_panel.cpp:39` (bug; found by: Editor UI)

editor_context::camera() is consumed only by view.pick / view.focus / the gizmo matrices. Nothing hands it to the renderer: renderer_subsystem extracts views only from scene camera_components and targets the whole swapchain, and the Viewport panel is an ordinary opaque ImGui window (editor_panel::draw calls ImGui::Begin(title,&open) with no NoBackground flag). 09 section 4 item 15(d) records only --offscreen/view.screenshot; the windowed editor is affected the same way and that is not recorded.

**Smallest fix:** Add a renderer hook for an extra render_view (editor camera -> render target), show it with ImGui::Image in the Viewport panel (design 805), and until then state the limitation in 09 section 4 instead of only for --offscreen.

### B11. A scene made with File > New Scene can never be saved from the UI

`engine/src/editor/ui/editor_workspace.cpp:57` (bug; found by: Editor UI)

The menu fires scene.new with only a name, so the scene path is empty; Save Scene and Ctrl+S are both gated on a non-empty path and there is no Save Scene As anywhere in the UI.

**Smallest fix:** Add Save Scene As... (path input -> scene.save_as), fall back to it from Save/Ctrl+S when the path is empty.

### B12. The [downloaded] decoder case fails (not skips) as soon as the documented asset download has run, which CI does on every leg

`tests/audio/test_decoder.cpp:404` (bug; found by: Tools and test infrastructure)

`audio.decoder - [downloaded] ogg, mp3 and flac decode...` is in the default unit run (labels audio;unit). Its precondition only checks the tests/.assets_ready stamp; tools/test_assets.json has no audio/tone.* entry, so once the stamp exists the case hits REQUIRE(exists(path)) and fails. ci.yml:105-106 runs `python tools/download_test_assets.py` before `ctest --preset` on all five legs, so every PR leg goes red; so does any developer who follows the download instruction. 09_cross_area_resolutions item 13d records this as 'the case skips', which is only true while the stamp is absent.

**Smallest fix:** Add the three CC0 tone clips to tools/test_assets.json (and the lock), or until then make the case skip when the specific files are missing (a per-file precondition) and correct item 13d.

### B13. --ai-stdio and --exec write log lines to stdout, corrupting the NDJSON protocol stream

`engine/src/core/foundation/log.cpp:207` (contract; found by: Lens: concurrency)

The console sink sends every message below WARN to stdout and nothing disables or redirects it in stdio mode, so the protocol stream on stdout is interleaved with ANSI-coloured log lines. docs/design/04_editor.md:397 promises: "With `--ai-stdio`, logging goes to stderr and file, never stdout." The editor-ai-control skill and docs/api/editor/ai-protocol.md say the same ("logs on stderr").

**Smallest fix:** When aiStdio is set (or --exec writes to stdout), route the console sink entirely to stderr before any subsystem logs (e.g. a console_log_sink stream option set in editor_application::initialise), and add an editor test that asserts every stdout line of an --ai-stdio run parses as JSON.

### B14. Every .gltf/.glb is imported as a physics collision mesh, never as a render model

`engine/src/assets/asset_importer.cpp:253` (bug; found by: Lens: error handling and lifetime)

Two importers claim .gltf/.glb (physics collision_mesh_importer.cpp:29 `EXTENSIONS = {".gltf", ".glb", ".obj"}` and renderer GLTF_EXTENSIONS). find_for_path breaks ties with `if (matched > bestLength && ...)`, so the first registered wins, and application.cpp starts physics_subsystem before renderer_subsystem. Design 14_physics.md:837 says the .glb is a render model that can be imported 'a second time' as collision geometry.

**Smallest fix:** Make the renderer importer the default for .gltf/.glb: drop those extensions from the collision importer's default extension list (keep it selectable by .meta importer id), or give importers a priority and add a test that a fresh .glb resolves to conjure.renderer.gltf.

### B15. Component voices are retained and never released: voice table leaks, destroyed sources keep playing

`engine/src/engine/subsystems/audio_subsystem.cpp:298` (bug; found by: Lens: determinism and performance)

Every voice started for an audio_source is created with retain = true, and nothing in the engine ever calls audio_engine::release (or stop) for it. Finished voices are orphaned in the 512-entry voice table and voices of destroyed entities keep sounding.

**Smallest fix:** In finish_one_shots and the invalid-handle branch call engine.release(voice) before clearing the handle, and register the REMOVED observer of design 12 (release on component removal / entity destroy). Add a test that plays 600 one-shots and one that destroys a looping source.

### B16. .gltf/.glb are imported by the physics collision-mesh importer, never as a renderer model, in the real engine

`engine/src/assets/asset_importer.cpp:220` (bug; found by: Gap round: protocol and file format security fuzz)

Two importers claim .gltf/.glb (physics collision_mesh_importer and renderer gltf_asset_importer). importer_registry::find_for_extension returns the first registered, and application.cpp registers physics_subsystem (line 430) before renderer_subsystem (line 433), so a fresh glTF always gets `"importer": "conjure.physics.collision_mesh_importer"` pinned into its .meta and yields a conjure.physics.collision_mesh, not a model with meshes/materials/textures. The integration test only passes because its private pipeline registers the renderer importer alone.

**Smallest fix:** Make extension conflicts explicit: either reject a second importer for an already-claimed extension, or give importers a priority / let one source feed several importers (model as primary, collision mesh as a sub-asset or opt-in via meta). At minimum register the renderer importer first and add an editor command test that imports a .gltf through the real application and expects a model.

### B17. Any non-UTF-8 string in a protocol reply aborts the editor (FATAL assertion); a project folder with one accented letter is enough

`engine/src/editor/core/protocol/protocol_message.cpp:150` (bug; found by: Gap round: unicode long paths portability)

The reply serialiser asserts on invalid UTF-8 instead of sanitising or failing the one request. Because conjure_editor has no UTF-8 code-page manifest, every `path.generic_string()` the commands put into replies/events/error messages is ANSI on Windows, so a project under e.g. `C:\Users\José\` kills the editor on the first `editor.state`. The same abort is reachable with pure ASCII paths through file content: `script.read` of a Latin-1 .cs file.

**Smallest fix:** In `serialise(protocol_response/event)` validate strings and replace invalid sequences with U+FFFD (or answer INTERNAL for that request) instead of asserting; make script.read reject/escape non-UTF-8 sources; and fix the root cause (next finding).

### B18. [downloaded] decoder case fails (not skips) on every CI leg once the asset download succeeds

`tests/audio/test_decoder.cpp:416` (build-ci; found by: Gap round: design docs vs code drift)

`decoder - [downloaded] ogg, mp3 and flac decode to the expected length within 1 %` lives in the ordinary `conjure_audio_tests` executable (labels `unit;audio`, tests/audio/CMakeLists.txt has no LABELS), so the default presets run it. Every leg of ci.yml and nightly.yml runs `python tools/download_test_assets.py` first, which writes `tests/.assets_ready`; `precondition::DOWNLOADED_ASSETS` then holds and the case hits `REQUIRE(std::filesystem::exists(path))` for `audio/tone.ogg`, which tools/test_assets.json does not list (its only audio entry, line 42, is a disabled placeholder whose url points at a README.md). 09 section 4 item 13(d) and docs/handbook/modules/audio.md:359 both record this as "the [downloaded] decoder case skips" - the record is wrong: it only skips where nothing was downloaded (a developer machine). It also contradicts 08_testing D12 ("those tests live in their own downloaded-labelled executable"; `conjure_downloaded_tests` does not exist).

**Smallest fix:** Either list CC0 tone.ogg/mp3/flac in tools/test_assets.json (and pin them), or until then turn the two REQUIREs into a 77 skip (`CONJURE_TEST_REQUIRE`-style) and move the case into a `downloaded`-labelled executable as D12 specifies; correct 09 item 13(d) and audio.md:359.

## Major findings

### Editor commands and protocol (21)

- **An atomic editor.batch is not rolled back while playing (and inside undo/redo)** (`engine/src/editor/core/command_dispatcher.cpp:513`, bug). record_outcome returns on `mUndo->frozen()` (and on mSuppressRecording) before the `mBatch` branch, so during play no child inverse reaches batch.entry.undo and the rollback loop has nothing to dispatch. The branch at line 261 (`if (mUndo->frozen()) note_unrecorded_edit`) is therefore dead. *Fix:* In record_outcome, when mBatch != nullptr always collect the inverse/replay (move the batch branch above the frozen and suppress checks); decide about the undo stack only when the batch ends. Add a play-mode case to test_batch_command.cpp.
- **component.set / component.remove can corrupt scene bookkeeping (guid index, hierarchy)** (`engine/src/editor/core/commands/commands_component.cpp:154`, bug). Only the transform is protected. Scene-managed components (conjure.scene.guid, conjure.scene.parent, name...) are written or removed raw through ecs::component_from_json / remove_raw, bypassing scene::set_guid / set_parent, and reflection.components even reports conjure.scene.parent as `editable: true`. *Fix:* In access::add_component / write_component / remove_component route guid, parent, name, disabled and prefab markers through the scene API (or refuse them with INVALID_ARGS naming the right command) and mark the hierarchy components EDITOR_HIDDEN.
- **scene.save / scene.save_as (and prefab.apply) during play write the play-time state to disk** (`engine/src/editor/core/commands/commands_scene.cpp:372`, bug). These commands are not EDITING_ONLY; while playing they serialise the running world, clear the dirty flag, and play.stop then restores the snapshot, leaving the file different from the editor scene with dirty=false. *Fix:* Add command_flags::EDITING_ONLY to scene.save, scene.save_as and prefab.apply (or save the play snapshot instead of the live world); update 04_editor.md 4.4.
- **File-system commands run during play are permanent and un-undoable although the warning says play.stop discards them** (`engine/src/editor/core/play_controller.cpp:191`, bug). While the undo stack is frozen record_outcome drops the inverse of every MUTATES command, including asset.delete, script.write, script.delete, asset.set, project.set_settings, which play.stop cannot restore. *Fix:* Flag the file-mutating asset.*, script.*, prefab.create/apply and project.set_settings commands EDITING_ONLY, or record their inverses even while frozen (they do not touch the scene).
- **asset.import (and asset.restore) overwrite an existing asset without capturing it; a failed import leaves it destroyed** (`engine/src/editor/core/commands/commands_asset.cpp:248`, bug). The copy-in path writes the destination before anything is validated and never checks whether the destination exists; the recorded inverse is asset.delete, and on an import failure nothing is rolled back (D4). *Fix:* Refuse an existing destination unless `overwrite:true`; when overwriting capture the old bytes as the inverse (asset.restore) and on any failure after the write remove/restore the file.
- **Requests pipelined behind project.open execute against the old project and are then silently lost** (`engine/src/editor/core/editor_context.cpp:257`, bug). project.open only schedules the restart; tick() keeps dispatching the rest of the frame's inbound requests on the old engine, answers them ok, and the restart then discards their effects (or leaves them in the wrong project). *Fix:* In tick(), stop dispatching once mHost->has_pending_project_open() and keep the remaining requests queued for the frame after the restart (rebind must not clear them); emit an event/warning when the restart fails.
- **<project>/.conjure/ai_port is written only for the start-up project** (`engine/src/editor/core/protocol/protocol_server.cpp:45`, contract). The port file is written once in start(); after project.open (or when the editor started without --project) the new project has no ai_port and the old project keeps a file pointing at an editor that no longer has it open. SKILL.md and ai-protocol.md tell agents to read this file. *Fix:* Add protocol_server::set_project_root(path) that removes the old file and writes the new one; call it from apply_pending_project_open and after a successful start without a project.
- **A client that half-closes after sending (printf ... | nc) gets its requests dropped without any response** (`engine/src/editor/core/protocol/tcp_transport.cpp:204`, bug). recv()==0 marks the connection closing and clears outbound; the lines already framed are reported together with the close, and protocol_server::on_client_closed erases the client's backlog before anything is dispatched. *Fix:* On a read-side close keep the connection in a 'draining' state: dispatch the requests already received, flush their responses, then close (only a send failure should drop the backlog).
- **--ai-token does not gate the event stream: unauthenticated clients receive every default event** (`engine/src/editor/core/protocol/protocol_server.cpp:298`, security). on_client_opened installs the event sink immediately and deliver_event never checks client.authenticated, so any local process can connect, never say hello and still read scene.loaded / scene.changed / selection / script and asset events. *Fix:* Return early from deliver_event while !client->authenticated (or register the sink only in mark_authenticated); add a server test.
- **console_buffer returns records whose text was overwritten after the text ring wraps a second time** (`engine/src/editor/core/console_buffer.cpp:149`, bug). The eviction loop stops at the first oldest entry that does not overlap the new record. After a wrap the oldest entries can be leftovers at the tail of the buffer (not overlapped), so the entries at the start of the buffer that the new record does overwrite stay alive with garbage text; from then on stale entries accumulate until the entry capacity. *Fix:* On wrap first drop every oldest entry whose textOffset >= the pre-wrap head, then run the overlap loop (or track the valid byte window explicitly); add a multi-lap test with mixed sizes that checks every returned text.
- **Undo of a bulk create is quadratic: 10,000 entities take ~11 s (create takes 0.16 s)** (`engine/src/editor/core/commands/command_support.cpp:258`, performance). entity.destroy_many (the inverse of entity.create_many / entity.duplicate / prefab.instantiate) runs outermost() with an O(n^2) is_ancestor_of + duplicate scan, then sorts with tree_position(), which for roots is a linear scan of scene.roots() per comparison (commands_entity.cpp:282-284). *Fix:* Build a hash set of the requested entities and walk each entity's ancestors once (O(n*depth)); precompute sibling/root indices in one pass before sorting.
- **Generated Game.csproj globs obj/**: every rebuild warns CS2002 and a second configuration breaks the build with CS0579** (`engine/src/editor/core/commands/commands_script.cpp:60`, bug). `<Compile Include="**/*.cs" />` with EnableDefaultCompileItems=false has no Exclude, so MSBuild's generated files under scripts/obj/<config>/ are compiled again. *Fix:* `<Compile Include="**/*.cs" Exclude="bin/**;obj/**" />` in CSPROJ_TEMPLATE.
- **physics.raycast and view.pick mode:"physics" never hit anything while EDITING** (`engine/src/editor/core/commands/commands_physics.cpp:20`, contract). The header comment and design 3.8/D10 present physics queries as usable in the editor ('the bodies are exactly what the scene describes'), but no body exists until the simulation runs. *Fix:* Make the physics subsystem create/sync bodies in the paused (EDITING) sync phase, or answer NOT_AVAILABLE/WRONG_PLAY_STATE while editing and correct the comment and docs.
- **view.screenshot on a real device succeeds with an image of the clear colour; camera and scene are never rendered** (`engine/src/editor/core/screenshot_service.cpp:41`, contract). The renderer backend creates a render target and reads it back without any view being rendered into it, so in the windowed editor the command reports success for a blank PNG. 09 item 15(d) only records that --offscreen falls back to the null device; the blank windowed result is not recorded. `camera`, and the design's `format:"jpg"` (04_editor.md:368), are unsupported/ignored. *Fix:* Until the renderer offers a view hook answer NOT_AVAILABLE instead of ok (or read back the swapchain/viewport target), and record the gap in 09 section 4; drop jpg from the design or implement it.
- **Two pending screenshots share one render target: the first gets the wrong image, the second fails** (`engine/src/editor/core/screenshot_service.cpp:61`, bug). renderer_screenshot_backend keeps a single mTarget; begin() of a second request destroys the first request's target, capture() of the first then reads the second's target (wrong size, reply still states the first's width/height) and destroys it, and the second capture fails with 'no render target to read back'. *Fix:* Keep the render target id in the pending entry (begin returns a handle, capture takes it) instead of in the backend.
- **A module whose manifest name is "editor" removes every built-in command when it unloads** (`engine/src/editor/core/editor_module_consumer.cpp:164`, bug). Built-in commands are registered with owner "editor" (command_support.cpp:556) and module commands with owner = manifest name; detach() calls remove_owned_by(owner), and "editor" is a valid module name ([a-z0-9_.]). *Fix:* Give built-ins a reserved owner that is not a valid module name (e.g. "<builtin>") or reject that manifest name in editor_module_consumer::validate.
- **An unknown command with a long name freezes the editor: didYouMean runs Levenshtein over the whole name** (`engine/src/editor/core/command_registry.cpp:173`, performance). closest_names computes a full edit-distance table against every registered command for any name, and a line may be 16 MiB. *Fix:* Skip suggestions (empty didYouMean) when the name is longer than e.g. 64 bytes, and cap the distance.
